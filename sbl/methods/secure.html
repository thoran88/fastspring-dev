Passing the payload

Either before the SBL script loads (fscSession), or dynamically after (secure()): 

<script>
var fscSession = {
  secure: { payload: securePayload, key: secureKey }
};
</script>
<script id="fsc-api" src="..." data-storefront="..." data-access-key="..."></script>
fastspring.builder.secure(securePayload, secureKey);
Dev-testing shortcut: for test orders only, pass plain unencrypted JSON with secureKey as an explicit empty string: fastspring.builder.secure(nonEncryptedJSON, ""); — omitting the second argument entirely (rather than passing "") also gets rejected. The demo below uses this path by default; the section after it uses real AES+RSA encryption, not the shortcut.

Real encryption — verified

The dev-testing shortcut above proves secure() works, but not that real encryption does. This section actually encrypts the payload: AES-128-ECB for the JSON, then the AES key itself RSA-encrypted with the real private key at ~/.fastspring/privatekey.pem — exactly the Java/PHP logic above, run for real by a tiny local Node server (sbl/server/secure-payload-signer.js), never in browser JS. Verified with a standalone round-trip test (encrypt with the private key, decrypt with the public cert FastSpring already has) before ever touching the network: AES key and payload both came back byte-for-byte identical. 

# start it once, separately, before using the button below
node sbl/server/secure-payload-signer.js
var payload = JSON.parse(document.getElementById('secure-json').value);
fetch('http://localhost:8124/sign', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(payload)
})
  .then(function (r) { return r.json(); })
  .then(function (signed) {
    fastspring.builder.secure(signed.securePayload, signed.secureKey);
    fastspring.builder.checkout();
  });
