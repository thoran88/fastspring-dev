Callbacks script tag + method param

Every page on this site is already wired to the four script-tag-level callbacks below — that's what powers the "Live event log" panel you've been watching. This page explains what each one is for, plus the separate per-method callback pattern.

Script tag callbacks

AttributeFires whenSignature
data-data-callback the session data updates — after essentially any add/update/remove/promo/etc. function (data) { ... }
data-popup-closed the checkout/cart popup window closes function (data) { ... } — data includes order id / purchase reference when a purchase completed
data-popup-webhook-received a webhook arrives while the popup is open (e.g. order completed server-side) function (data) { ... } — webhook payload with order/customer details
data-error-callback a builder call fails validation server-side (bad promo code, unsigned authenticate(), etc.) function (data) { ... }
Note: these are wired once, on the script tag itself — every page here uses the same four function names (dataCallback, popupClosed, webhookReceived, errorCallback), defined in assets/log.js.

Source — script tag wiring

<script
  id="fsc-api"
  src="..."
  data-storefront="your-storefront-URL"
  data-data-callback="dataCallback"
  data-popup-closed="popupClosed"
  data-popup-webhook-received="webhookReceived"
  data-error-callback="errorCallback">
</script>

Per-method callback

Separately, most builder methods accept an optional trailing callback that fires only when that specific call completes — useful when you need to know "did this add finish" rather than reacting to every session-wide data update. 

fastspring.builder.add('prod-1', function (data) {
  // fires only for this add() call, in addition to data-data-callback firing too
  console.log('this specific add finished');
});
